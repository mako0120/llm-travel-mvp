# 05. Canva Standards(Canva 移植標準)

## 前提

- Canva コネクタ(MCP)は**未接続**が既定状態。接続にはユーザーの OAuth 承認が必要(承認境界)。
- 接続前提の作業を約束しない。未接続の間は「Canva ブリーフ(移植仕様書)」を成果物とする。

## Canva ブリーフとは

人間(または接続後の自動化)が Canva 上でデッキを再現するための仕様書。`templates/canva_brief_template.md` を使う。必須項目:

- デッキ名・目的・想定視聴者
- スライドごとの: レイアウト種別 / 見出しテキスト / 本文テキスト / 図版指示 / 配色指定(HEX)
- フォント指定(Canva 内で近いもの: 例 Yu Gothic → Noto Sans JP)
- 使用するCanva要素の種類(グリッド、カード、バッジ、チャート)
- アニメーション指定(使う場合のみ。既定は「なし」)

### 生成コスト削減(推奨手順)

`canva_brief.md` は「前提」「レイアウト種別 → Canva要素の対応」「移植手順」
「検品チェック」の大部分が全テーマで共通の定型文であり、`scripts/gen_canva_brief.py`
が `deck_spec.json` から自動生成できる(パレットHEX・レイアウト一覧・カード枚数・
スライド枚数を`deck_spec.json`から自動検出するため、手書きより情報が欠落しない)。
LLM(Claude)が書くべきなのは、テーマ固有の「想定視聴者の一文」「実在企業名」
「このデッキ固有の注意の箇条書き」「検品チェックの固有項目」のみに絞り込み、
それを小さな input.json として渡す:

```
python scripts/gen_canva_brief.py <deck_spec.json> <input.json> <output.md>
```

`input.json` の形式はスクリプト冒頭のdocstring参照。定型部分を毎回書き直す
必要がなくなるため、テーマ1本あたりの出力トークン数(API利用量)を削減できる。
出力内容は手書き版と同等以上の情報量になるよう設計されている(検証済み:
既存241テーマ全件のdeck_spec.jsonに対してエラーなく生成できることを確認済み)。

## デザイン規則

- PowerPoint 版と同一パレット・同一構成を維持する(ブランド一貫性)。
- Canva テンプレートをそのまま流用する場合はライセンス(無料/Pro素材)をブリーフに明記する。
- Pro 素材・有料素材の使用は課金に関わるため人間承認が必要。

## 接続後の自動化(将来)

Canva コネクタが承認・接続されたら:

1. ブリーフからデザインを自動生成するフローを Issue 化して提案する。
2. 生成結果の公開・共有リンク発行は人間承認の後に行う。
