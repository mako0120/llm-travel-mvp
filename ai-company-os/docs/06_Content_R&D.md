# 06. Content R&D(コンテンツ調査・研究)

## 調査の原則

- 情報源の優先順位: 公式ドキュメント > 公式発表 > 一次リポジトリ > 論文 > 信頼できる技術ブログ > コミュニティ(発見用途のみ)。
- 取得できない情報を推測で埋めない。「不明」と記録する。
- すべての事実に URL 出典を付ける。出典のない数字は使わない。
- 記録は4分類: 検証済み事実 / 合理的推測 / 推奨 / 不明。

## 調査レポート

`templates/research_report_template.md` を使う。必須構成:

1. 調査目的と問い
2. 検証済み事実(出典付き)
3. 比較表(候補ごとに: 提供元 / 用途 / 導入条件 / ライセンス / 更新状況 / セキュリティ / 期待効果 / リスク / 判定)
4. 判定: adopt / trial / watch / reject
5. 不明点と追加調査計画

## コンテンツ研究の観点(動画・記事・プレゼン共通)

- タイトル: 数字・ベネフィット・具体性の有無
- 構成: 冒頭30秒(スライドなら最初の3枚)で課題提示できているか
- 維持: 1トピック1メッセージ、転換の頻度
- CTA: 次のアクションが1つに絞られているか
- 対象: 初心者向け/専門家向けの明示

## テーマ選定モード(2026-07-21〜、オーナー指示によりデフォルト運用)

テーマ選定は2つのモードを使い分ける。指示がなければ**バイラル優先モード**をデフォルトとする。

### モードA: 評価表モード(従来)

`research_report_template.md` の9項目採点(日本需要・新しさ・参入余地・実用性・継続性・
差別化・スライド化・Shorts性・収益化、100点満点、70点未満は不採用)で候補を比較する。

### モードB: バイラル優先モード(デフォルト)

「再生数がとれている、または取れそうなコンテンツ」を優先して選ぶ。日本・海外どちらも対象。

- 採用条件: **実証済みのバイラル実績**があること。例: 実際にSNSでトレンド入りした
  (X公式トレンドページ等で確認できる)、複数の信頼できるメディアが「話題」「バズった」
  と報じている、公式発表の実績数値(会員数・売上急増等)が確認できる、など
- **却下条件**: SEO対策ブログ・AI動画生成ツールの宣伝記事が主張する再生数(「◯◯万回再生」
  等)は、一次ソース(実際の動画URL)が示されない限り採用しない。不自然に丸い数字・
  検証不能な数字は信頼性が低いと判断し除外する
- 出典の優先順位はモードAと同じ(公式発表・信頼できる報道 > SEOブログ)
- 対象ジャンルの配分(AI/エージェント系70%・海外/国内で活躍する日本人20%・
  急成長アカウント10%)は維持するが、各枠内でモードBの基準を優先する

## 2026-07-24追記: 「常に最新」の原則(オーナー指示)

過去の評価表(`ai-company-os/research/*theme-evaluation*.md`)に、点数は高いが
ジャンル配分等の理由で見送っていた「未制作の候補」が残っていても、**それを
機械的に使い回さない**。定期実行の着手時点で毎回、その時点の最新ニュースを
確認し直し、それでもなお最良の候補であれば採用する、という運用にする
(過去の候補をそのまま採用してよい場合と、より新しい候補に差し替えるべき
場合があるため、着手時点での確認を欠かさない)。

## 2026-07-27追記: 鮮度の数値基準の明確化(オーナー指示)

「常に最新」の原則(上記)を、具体的な数値基準として明確化する。

- 新規調査で候補を採用する際は、**着手日の前日以内(1日前まで)の発表・報道を
  基本とする**。それより古い候補しか見つからない場合は、機械的に妥協して
  古い候補を採用せず、検索クエリを変える(切り口・業種・地域を変える等)、
  検索回数を増やす等して、着手日または前日の候補を探す努力を先に尽くす
- 十分に探しても着手日・前日の候補が見つからない場合に限り、より古い候補を
  やむを得ず採用してよいが、その場合は**具体的な発表日と「何日前か」を
  README・research.mdの選定理由に明記**し、鮮度で妥協した理由を正直に書く
  (例: 「新規性の高いAI/エージェント系候補が直近1〜2日で見つからず、
  7日前の発表だが実用性・日本需要が高いため採用」)
- 定期実行の1サイクル内で複数回リサーチが必要になる場合(候補が尽きた場合の
  再調査等)も、この基準は毎回同じ着手日を基準に適用する
- この基準は「AI/エージェント系」枠だけでなく、「海外/国内で活躍する日本人」
  「急成長アカウント」の各枠にも同様に適用する

## 2026-08-05追記: 鮮度基準を「着手日から2日以内」に厳格化(オーナー指示、上記を更新)

136本目(Lyzr、発表から26日経過)の採用を受け、オーナーから「それでも2日前が
条件」との明確な指示があった。これにより、上記(2026-07-27追記)の
「古い候補もやむを得ず採用してよい」という妥協的な運用を終了し、以下に
差し替える。

- **候補の採用条件は、着手日を含めて2日以内(着手日または前日)の発表・報道を
  必須とする。** これを満たさない候補は、実用性・知名度・スコアがどれだけ
  高くても採用しない(GIM・Antioch・Lyzr等でこれまで行っていたような、鮮度を
  正直に開示した上での妥協採用は今後行わない)
- 2日以内の候補が見つからない場合は、機械的に諦めず検索を継続する
  (クエリの切り口・業種・地域・言語を変える、検索回数を増やす等)。
  **海外発の話題(米国・欧州・その他地域のバズ)も等しく対象**であり、
  日本関連に限定する必要はない。国内外を問わず2日以内の候補を優先的に探す
- 上記の探索を尽くしてもなお2日以内の候補が1本も見つからない場合に限り、
  その旨(具体的に何を試したか)を評価表に正直に記録した上で、次点として
  最も新しい候補を暫定的に採用してよいが、これは例外的な最終手段であり
  常態化させない
- この基準は「AI/エージェント系」枠、「海外/国内で活躍する日本人」枠、
  「急成長アカウント」枠のいずれにも同様に適用する

## 2026-08-05追記: 1日あたりの制作上限とフィード公開のタイミング(オーナー指示)

- **1日あたりの制作本数上限は12本**とする。定期実行トリガーが1回の発火で
  2本ずつ制作する運用のため、1日6サイクルが目安の上限となる。これは
  APIの週次/セッション利用上限に達して作業が中断する事態を避けるための
  ペース配分であり、上限に達した場合はその日の制作をそこで打ち切り、
  翌日以降に持ち越す(無理に上限を超えて続行しない)
- **その日最後の動画(ナレーション動画)の制作・CI公開が完了した後**、
  「見出しフィード」(scratchpadのfeed.html、アーティファクトとして公開)
  にその日制作した全テーマを反映し、一覧画面として公開(再公開)する。
  それまでの各サイクル内での逐次更新に加えて、1日の作業の締めくくりとして
  必ず最新の一覧状態を反映したフィードを公開する
- 日次の制作本数・公開状況はNotion記録・PR履歴で追跡できるため、正確な
  本数のカウントはそれらを参照して行う(推測で「◯本目」と決め打ちしない)
- **1日の12本目(上限最後の1本)が完成した際の完了報告メッセージには、
  必ず見出しフィードのアーティファクトURLを添付する**(オーナー指示、
  2026-08-05追記)。フィード公開自体が失敗している場合でも、URLの案内と
  失敗している旨の正直な開示はあわせて行う
- 旧URL(`https://claude.ai/code/artifact/b02d4278-d54a-41fa-8aba-a6cc40e20518`)
  は2026-08-05、複数ラウンドにわたりHTTP 403で再公開不能な状態が続いた
  ため、同日中に新規URL
  (`https://claude.ai/code/artifact/5b01b618-29df-416f-891a-5352ec42626c`)
  へ切り替えた。以後はこちらを正とする
- **2026-08-11追記(訂正)**: 定期実行トリガーの文面には一貫して旧URL
  (`b02d4278-...`)が記載されており、オーナーが実際に開いて確認している
  のはこちらだった。5b01b618側だけを更新し続けた結果、オーナーから
  「urlに最近作られたやつのってない」との指摘を受けた。この時点で
  b02d4278への再公開を試したところ403エラーは発生せず正常に成功したため、
  **`https://claude.ai/code/artifact/b02d4278-d54a-41fa-8aba-a6cc40e20518`
  を正規URLとして復帰させ、以後はこちらを更新する**(上記2026-08-05の
  切り替え指示を本追記で上書きする)。今後、万一再度403等で公開できない
  場合は、その場でオーナーに正直に報告してから代替URLを検討すること
