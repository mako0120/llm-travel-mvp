# 01. Core Rules(絶対規則)

以下は他のすべてのドキュメントより優先される。

## 承認境界(人間承認なしに実行しない)

- `main` への直接 push / merge
- 本番公開・デプロイ・外部への発信(SNS投稿、動画公開、記事公開を含む)
- 課金・サブスクリプション契約・購入
- 新しい外部連携のインストール・OAuth 認可・権限付与
- 認証・データベース・環境変数・外部サービス設定の変更
- リポジトリの作成・削除・可視性変更

## 秘密情報

- API キー・トークン・`.env` 系ファイルを表示・保存・コミットしない。
- 秘密情報らしき文字列を発見したら、内容を出力せずに場所だけ報告する。

## 正直さ

- ツール・スキル・MCP・コネクタは**実際に検証してから**「利用可能」と言う。
- 分類は4値で記録する: `verified` / `usable with setup` / `unavailable` / `unsafe or unnecessary`。
- 検証できなかった品質チェック(例: ピクセル単位の見た目確認)は「できなかった」と明示する。

## 著作権

- 他者のスライド・画像・文章を無断でコピーするワークフローを作らない。
- 図・チャート・レイアウトは原則オリジナルで生成する。
- 引用は出典明記の短い引用に限る。
- 実写画像(ニュース写真・企業ロゴ・製品スクリーンショット等)を使う場合は、
  以下のいずれかで著作権上の再利用が確認できるものに限る(2026-09-11、
  オーナー承認済み: 「著作権に引っかからなければ良い」)。
  - パブリックドメイン / CC0
  - CC-BY・CC-BY-SA 等、表示義務を満たせば商用・改変利用可能なライセンス
    (出典・ライセンス名・帰属表示をresearch.mdに必ず記録する)
  - 発行元が「メディア掲載可」「報道・レビュー用に自由利用可」と明示した
    公式プレスキット素材
  - Canva等、商用利用ライセンス込みのストックコンテンツライブラリ経由の素材
  - 報道対象本人の一次情報としてのSNSスクリーンショット(2026-09-11、オーナー
    承認済み: 「報道対象本人の一次情報のみ」)。以下をすべて満たす場合に限る。
    - 投稿者がそのニュースの当事者本人(企業公式アカウント・経営者本人など)
      であり、そのニュースの一次ソースそのものである(第三者の反応・論評
      投稿は含まない)
    - 出典明記の短い引用として扱う(上記「引用」規定の範囲内)。投稿全文の
      無断転載ではなく、報道に必要な最小限の部分のみを用いる
    - アカウント名・投稿日時・URLをresearch.mdに記録する
    - 画面内に当事者本人以外の第三者の顔写真・アイコンが写り込む場合は、
      ぼかす・トリミングするなどして写り込みを避ける
  - 上記のいずれでも確認できない画像(無許諾の通常報道写真、当事者本人以外
    の第三者SNS投稿のスクリーンショット等を含む)は使用しない。確認できない
    場合は必ず既存の独自図解にフォールバックする。
  - **2026-09-12追記**: 実運用では、実写画像の取得自体がこの環境のネットワーク
    出口制限により技術的に不可能だった(WebFetch/curlともEGRESS_BLOCKED)ため、
    `scripts/generate_post_image.py`によるオリジナル生成デザイン(グラデーション+
    テキストのみ、実写素材不使用)に方針転換した。上記の実写画像許容条件は
    将来ネットワークアクセスが可能な環境向けに残しておくが、当面は適用されない。

## 利用規約の遵守

- 料金制限の回避、複数アカウントの併用、API の不正利用は行わない。
- 「無料化」「無制限化」をうたう非公式ツールは、公式ドキュメントで正当性を確認できない限り採用しない。

## 作業規律

- すべての変更は open な GitHub Issue から始める。
- ブランチは `claude/feature-<issue番号>-<slug>`。
- PR は Draft で作成し、本文に `Closes #<issue番号>` を書く。
- Issue のスコープ外を変更しない。無関係なリファクタリングをしない。
- 他のエージェント(chatgpt/, codex/)のブランチに上書きしない。
