## 概要欄(description)案

```
Rustのコア開発リポジトリ「rust-lang/rust」内の5つのチームが、2026年8月5日、
LLM(大規模言語モデル)利用に関する公式ポリシーを採択しました。質問への
回答・コード分析・非公開レビュー等にはLLM利用を認める一方、ドキュメント・
安全性コメント・コンパイラの診断メッセージのLLM生成、そしてLLMレビューに
よるマージ可否の判断は禁止されています。方針の核心は「LLMは、より良く
書くために使う。より速く書くためではない("write better, not faster")」
というものです。

なお、このポリシーはRustプロジェクト全体の統一見解ではなく、
「rust-lang/rust」というモノレポに適用される方針である点にご注意ください。

この動画では、
・何が起きたのか
・初心者向け: Rustとはどんなプログラミング言語か
・このポリシーはどこまでの範囲に適用されるのか
・LLM利用の「許可」と「禁止」の具体的な線引き
・方針の核心「write better, not faster」とは何か
・確認できたこと・できなかったこと・鮮度について
を、出典付きで整理して紹介します。

■ 主な出典
- Rust公式Inside Rust Blog(2026-08-05)「rust-lang/rust is adopting an LLM
  policy」
- Linuxiac「Rust May Limit AI-Generated Work in Its Core Repository」
- Socket.dev公式ブログ「Rust Moves to Restrict LLM Use in Contributions
  After Months...」
- rust-lang/rust-forgeリポジトリ Pull Request #1040(提案者: jyn514)

■ 重要な開示: 本動画の中立性について
本動画は、rust-lang/rustが実際に採択したポリシーの内容を中立的に報告する
もので、「AIコーディングツールは良いものか悪いものか」というAI活用全般に
ついての論評は行いません。実在プロジェクト名・実在人物名はテキストとして
のみ使用し、ロゴ・写真は使用していません。

■ 鮮度についての開示
発表は着手日(2026年8月5日)と完全に同日であり、docs/06_Content_R&D.mdで
2026-08-05に厳格化された「着手日から2日以内」の鮮度基準を、このシリーズで
可能な最高水準の形で満たしています。

■ 未確認事項について
Socket.dev見出しの「数か月」の具体的内容、他のRustチーム・Rust Foundation
全体への波及、ポリシー違反時の執行方法は、本調査の範囲では確認できて
いません。
```
